Part (a)

Linear Regression using basic R-package

lm() computes the closed-form OLS solution derived in Lecture 3: minimising \(E_{in}(\mathbf{w}) = \frac{1}{N}\|\mathbf{Xw-y}\|^2\) by setting the gradient to zero gives \(\mathbf{w}^* = (\mathbf{X}^T\mathbf{X})^{-1}\mathbf{X}^T\mathbf{y}\). No iterative algorithm (gradient descent) is needed here since linear regression has a closed-form minimiser, unlike logistic regression or the ANN in part (c).

bedrooms_median <- median(training$total_bedrooms, na.rm = TRUE)

training <- training |>
  mutate(total_bedrooms = if_else(is.na(total_bedrooms), bedrooms_median, total_bedrooms))

x_test <- x_test |>
  mutate(total_bedrooms = if_else(is.na(total_bedrooms), bedrooms_median, total_bedrooms))
final_fit <- lm(Price ~ ., data = training)

rmse <- function(actual, predicted) {
  sqrt(mean((actual - predicted)^2)) }

rmse(training$Price, predict(final_fit, training))

median_income has by far the strongest effect: each extra $10,000 of median block income is associated with roughly $40,000 higher predicted house price, holding other predictors fixed. total_rooms has a negative coefficient despite more rooms intuitively meaning a bigger/pricier block - this is a multicollinearity artefact, not a genuine effect: total_rooms, total_bedrooms, population, and households are all block-level totals that move together, so the model can’t cleanly separate their individual contributions. This is the kind of issue the ratio features in part (b) are meant to fix.

Part (b)

Part (b) builds four models on top of part (a), each building on the last: (1) engineered features fit with plain OLS, (2) the same features with ridge regularisation to address the collinearity the features introduce, (3) a log(Price) target transform to address the right-skew in Price itself, and (4) ridge regularisation combined with the log(Price) target, to check whether the two techniques help more together than separately. Model 3 is the final part (b) model.

Feature engineering: bespoke and polynomial features

  • rooms_per_household, bedrooms_per_room, population_per_household, rooms_per_person (Lecture 3 bespoke ratios) - directly target the multicollinearity from part (a), where total_rooms, total_bedrooms, population, and households were fighting each other as raw block-level totals
  • median_income_sq, housing_median_age_sq, income_x_age, longitude_x_latitude, longitude_sq, latitude_sq (Lecture 5 polynomial/interaction terms) - complete the canonical quadratic basis \(z = (1, x_1, x_2, x_1x_2, x_1^2, x_2^2)\) for median_income/housing_median_age and for longitude/latitude; the spatial terms let the model fit a diagonal price gradient along California’s coastline, which longitude/latitude alone (axis-aligned only) cannot
  • log_total_rooms, log_total_bedrooms, log_population, log_households - correct the heavy right-skew in those raw counts, which was producing extreme leverage points and negative predicted prices in part (a)’s residuals
  • dist_to_city - Euclidean distance (in degrees) from each block to the nearest of SF/LA/San Diego/San Jose, a geometric proxy for distance to a major job/price centre
  • age_capped - flags the 956 of 15,480 training rows where housing_median_age is top-coded at exactly 52 (“52+ years” rather than a precise age)
  • median_income:ocean_proximity (added in the model formula, not as a precomputed column) - lets income’s effect on price vary by location type
  • bedrooms_per_room is capped at 1: bedrooms can’t outnumber total rooms, and real (non-imputed) data never breaches that ratio, but a few rows have median-imputed total_bedrooms sitting on an atypically small block, which can push the uncapped ratio above 1 and produce unrealistic predictions further down the pipeline
city_coords <- tribble(
  ~city,       ~city_lon,  ~city_lat,
  "SF",        -122.4194,  37.7749,
  "LA",        -118.2437,  34.0522,
  "San Diego", -117.1611,  32.7157,
  "San Jose",  -121.8863,  37.3382
)

dist_to_nearest_city <- function(longitude, latitude) {
  dists <- sapply(seq_len(nrow(city_coords)), function(i) {
    sqrt((longitude - city_coords$city_lon[i])^2 + (latitude - city_coords$city_lat[i])^2)
  })
  apply(dists, 1, min)
}

engineer_features <- function(df) {
  df |>
    mutate(
      rooms_per_household = total_rooms / households,
      bedrooms_per_room = pmin(total_bedrooms / total_rooms, 1),
      population_per_household = population / households,
      rooms_per_person = total_rooms / population,
      median_income_sq = median_income^2,
      housing_median_age_sq = housing_median_age^2,
      income_x_age = median_income * housing_median_age,
      longitude_x_latitude = longitude * latitude,
      longitude_sq = longitude^2,
      latitude_sq = latitude^2,
      log_total_rooms = log(total_rooms),
      log_total_bedrooms = log(total_bedrooms),
      log_population = log(population),
      log_households = log(households),
      age_capped = as.numeric(housing_median_age == 52),
      dist_to_city = dist_to_nearest_city(longitude, latitude)
    ) |>
    select(-total_rooms, -total_bedrooms, -population, -households)
}

training <- engineer_features(training)
x_test <- engineer_features(x_test)

Standardisation

Per Lecture 5, features on very different scales (e.g. total_rooms in the thousands vs median_income in single digits) get arbitrarily different weight magnitudes, which matters once regularisation penalises ||w||. Standardise every continuous predictor to mean 0, variance 1 using training statistics only, applied to both training and test.

continuous_vars <- c(
  "longitude", "latitude", "housing_median_age", "median_income",
  "rooms_per_household", "bedrooms_per_room", "population_per_household",
  "rooms_per_person", "median_income_sq", "housing_median_age_sq", "income_x_age",
  "longitude_x_latitude", "longitude_sq", "latitude_sq",
  "log_total_rooms", "log_total_bedrooms", "log_population", "log_households",
  "dist_to_city"
)

train_means <- colMeans(training[continuous_vars])
train_sds <- sapply(training[continuous_vars], sd)

for (col in continuous_vars) {
  training[[col]] <- (training[[col]] - train_means[col]) / train_sds[col]
  x_test[[col]] <- (x_test[[col]] - train_means[col]) / train_sds[col]
}

With longitude, latitude, longitude^2, latitude^2, and longitude*latitude all in the model together, the individual coefficients on these terms are large and unstable - they’re highly collinear by construction, all five being functions of the same two raw variables over a narrow real-world range - even though the overall fit and predictions are fine. This is the exact symptom Lecture 5’s ridge penalty is designed to fix, which motivates Model 2.

Model 2: ridge regression with cross-validated lambda

Lecture 5’s augmented error adds a ridge penalty to the loss: \(E_{aug}(\mathbf{w}) = E_{in}(\mathbf{w}) + \frac{\lambda}{N}\|\mathbf{w}\|_2^2\), which also has a closed-form solution, \(\mathbf{w}^*_{\text{ridge}} = (\mathbf{X}^T\mathbf{X} + \lambda I)^{-1}\mathbf{X}^T\mathbf{y}\) - the same normal equations as part (a) with \(\lambda I\) added (the intercept is excluded from the penalty, standard practice, since there’s no reason to shrink the baseline level toward zero). \(\lambda\) is chosen by k-fold cross-validation, per the “Setting \(\lambda\)” / “Cross-Validation” slides: for each candidate \(\lambda\) on a grid, fit on \(K-1\) folds and evaluate on the held-out fold, then pick the \(\lambda\) with the smallest average out-of-sample error.

X <- model.matrix(Price ~ . + median_income:ocean_proximity, data = training)
y <- training$Price
X_test <- model.matrix(~ . + median_income:ocean_proximity, data = select(x_test, -ID))

ridge_fit <- function(X, y, lambda) {
  penalty <- lambda * diag(ncol(X))
  penalty[1, 1] <- 0  # don't penalise the intercept
  solve(t(X) %*% X + penalty, t(X) %*% y)
}
set.seed(3555)
k <- 5
folds <- sample(rep(1:k, length.out = nrow(X)))
lambda_grid <- 10^seq(-4, 4, length.out = 20)
cv_rmse <- numeric(length(lambda_grid))

for (i in seq_along(lambda_grid)) {
  lambda <- lambda_grid[i]
  fold_rmse <- numeric(k)

  for (fold in 1:k) {
    is_train <- folds != fold
    is_valid <- folds == fold

    w <- ridge_fit(X[is_train, ], y[is_train], lambda)
    predicted <- X[is_valid, ] %*% w

    fold_rmse[fold] <- rmse(y[is_valid], predicted)
  }

  cv_rmse[i] <- mean(fold_rmse)
}

best_lambda <- lambda_grid[which.min(cv_rmse)]
best_lambda
[1] 1e-04
tibble(lambda = lambda_grid, cv_rmse = cv_rmse) |>

Findings:

  • CV selects \(\lambda \approx 10^{-4}\), i.e. essentially no regularisation (\(\lambda \to 0 \approx\) OLS).
  • This doesn’t contradict the coefficient instability noted above - the individual coefficients on the five collinear spatial terms are still large and poorly determined.
  • It means that with \(n = 15{,}480\) training rows and only \(p = 29\) parameters, there isn’t enough variance in the predictions (as opposed to the individual coefficients) for shrinkage to pay off - in-sample R² for this model comes out effectively identical to Model 1 (0.694 vs 0.694).
  • Kaggle score for this model (submission_b_ridge.csv): 0.690 R².
  • Ridge is still the right tool to reach for as feature/parameter count grows (particularly once part (c)’s ANN is in play) - it just isn’t doing much work for this specific linear model, so Model 3 below builds on Model 1 (plain OLS) rather than on the ridge fit. The same ridge_fit() function, lambda grid, and fold assignment are reused again in Model 4, refit on the log(Price) target, to check whether combining the two techniques changes anything.

Model 3: log-transformed target

House prices are right-skewed, and part (a)’s residual plot showed a funnel shape (errors growing with predicted price) - both point to modelling log(Price) instead of Price directly. This is the final part (b) model.

fit_log <- lm(log(Price) ~ . + median_income:ocean_proximity, data = training)

predicted_log <- predict(fit_log, training)

log_resid <- log(training$Price) - predicted_log
smear <- mean(exp(log_resid))

predicted_price <- exp(predicted_log) * smear

rmse(training$Price, predicted_price)
[1] 62212.15
1 - sum((training$Price - predicted_price)^2) / sum((training$Price - mean(training$Price))^2)
[1] 0.7088576
test_pred_log <- predict(fit_log, newdata = x_test)
test_pred_price <- exp(test_pred_log) * smear

submission_log <- tibble(ID = x_test$ID, Price = test_pred_price)

write_csv(submission_log, here::here("submissions/submission_b_log.csv"))

Notes:

  • Naive back-transform (exp(predicted_log)) is biased low - by Jensen’s inequality, \(E[\exp(X)] \geq \exp(E[X])\), so exponentiating a prediction of the mean of log(Price) underestimates the mean of Price. smear (Duan’s smearing estimator: the average of exp(residual) on the log scale) corrects for this.
  • Every prediction is exp(...), so they’re guaranteed positive - this resolves the negative-predicted-price extrapolation issue flagged in part (a).
  • Builds on Model 1’s feature set (not Model 2’s ridge fit), since Model 2 found regularisation unnecessary here.
